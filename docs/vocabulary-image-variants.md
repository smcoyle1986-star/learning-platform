# Static vocabulary image variants

Vocabulary artwork keeps its original PNG (or source image) in `vocab-images` as the master asset. The browser uses public, pre-generated WebP files at:

`derived/v2/<original path without extension>-160.webp`
`derived/v2/<original path without extension>-480.webp`
`derived/v2/<original path without extension>-1024.webp`

These files are not generated by Supabase Image Transformations. They use one-year immutable cache headers because their path is versioned.

## Existing artwork

First inspect the safe no-write plan:

```bash
npm run vocab-images:variants
```

Add `-- --estimate` to download a small representative sample and estimate the additional storage. It still does not upload or change any file.

Then create the missing variants:

```bash
npm run vocab-images:variants -- --write
```

For a small smoke test, use `-- --write --limit 6` first. The script is safe to rerun: existing immutable derivatives are skipped. It never deletes or changes a master image.

Use `-- --write --paths nouns/dog/dog_1.png,verbs/wake_up/wake_up_1.png` when a specific representative smoke-test set is needed.

## New or replacement artwork

The noun image-generation pipeline creates static variants immediately after it uploads a master image. Imported vocabulary artwork should run the command above after its normal import.

When deliberately replacing an existing master at the same path, use a new source filename/path whenever possible. If a stable source path must be reused, increment `VOCABULARY_STATIC_VARIANT_ROOT` in `lib/images/storage.ts`, regenerate the affected variants, and deploy together. That cache-version step prevents a browser from retaining the older WebP for its one-year immutable lifetime.
